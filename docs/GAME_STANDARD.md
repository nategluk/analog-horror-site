# GAME STANDARD

Компактный UX/runtime-контракт для новых сюжетных игр «Детского Жира».
Референс поведения — Красная комната. Это не требование копировать её сюжет,
визуальный стиль или весь `js/lora-red-room.js`.

## 1. Базовый экран

- Один cinematic stage `16:9`, заполняющий доступную область на desktop и mobile.
- Под ним или поверх безопасной зоны: speaker, короткая реплика и choices.
- Сюжетно важное всегда доступно в тексте. Звук добровольный.
- На `390x844` нет горизонтального overflow; интерактивные цели не меньше `44px`.
- Типы текстовых блоков едины: персонаж, `Я`, `СИСТЕМА`, `ЗАПИСКА`.

## 2. Реплики и choices

- Цель для реплики — до `80` знаков; hard limit — `160`.
- Цель для кнопки — до `26` знаков; hard limit — `40`.
- Одновременно видно не больше четырёх смысловых кнопок. Больший набор разбивается
  группами вроде `УТОЧНИТЬ`, `СПРОСИТЬ ПРО`, `ПОКАЗАТЬ` с возвратом назад.
- Одна кнопка — одно понятное действие игрока. Не показывать числовые параметры.
- Исключение из hard limit допускается только явным полем `allowLongText` или
  `allowLongChoice`, чтобы validator мог отличить решение от случайности.

## 3. Живое состояние сцены

Каждая важная сцена объявляет роли media, а не просто один файл:

| Роль | Поведение |
|---|---|
| `neutral` | короткий бесшовный loop, пока игрок читает и выбирает |
| `active` | альтернативный loop для изменившегося состояния/настроения |
| `burst` | редкое одноразовое действие; затем возврат в текущий loop |
| `transition` | появление, уход или необратимая смена сцены по `video.ended` |
| `hold` | still последнего устойчивого состояния |
| `fallback` | still для ошибки media и `prefers-reduced-motion` |

- Диалог не должен становиться статичным после первого проигрывания media.
- Burst не перезапускается при простой перерисовке того же узла.
- Transition не повторяется после reload, если её последствие уже сохранено.
- Ошибка видео возвращает fallback и оставляет choices доступными.
- Motion с персонажем начинается с принятого neutral plate и возвращается в
  совместимое состояние; случайный общий poster не используется.

## 4. Lifecycle персонажа

Присутствие задаётся состоянием, а не выводится из комнаты или старого poster:

`absent → arrives → present-neutral/active → leaves → absent`

- После `leaves` полноэкранный персонаж не может вернуться без отдельного
  сюжетного события.
- Появление на CCTV, фотографии или другом экране — отдельное visual-state и не
  означает физическое присутствие в комнате.
- Intro, разговор, уход и post-exit получают разные visual IDs.

## 5. Контентный узел

Минимальный узел содержит `speaker`, `text/line`, `visual`, `choices` и при
необходимости `sound`, `set/require`, `autoNext`, `complete`.

Visual ID ссылается на media-state с `neutral/active/burst/transition/hold`, а не
на случайный fallback. Node-specific burst объявляется отдельно и не плодит
новую копию базовой сцены.

## 6. Audio

- У игры есть тихий optional ambient bed и короткие event cues.
- Сначала проверять общий каталог на `REUSE`; затем `REPROCESS`; только потом
  составлять `GENERATE` для ElevenLabs.
- Один cue не должен изображать разные физические события только потому, что
  файл уже существует: дверь, стук, цепь и люк — разные категории.
- Звук не автозапускается до добровольного действия пользователя и не несёт
  единственную сюжетную информацию.

## 7. Save, resume и replay

- У каждой игры собственный versioned localStorage key.
- Сохраняются текущий узел, flags, необратимые transitions и итог.
- Reload возвращает устойчивое состояние без повтора появления/ухода и без
  возврата исчезнувшего персонажа.
- После финала доступны `Начать новую смену/сессию` и выход к связанной странице.
- Replay сбрасывает только ключ этой игры; профиль, другие игры и режим сайта не
  очищаются. Канонические IDs/flags меняются только с миграцией.

## 8. Проверки

- На каждом изменении: `git diff --check`; для JS — `node --check`.
- Контент: validator проверяет reachability, ссылки, лимиты текста, максимум
  видимых choices и известные visual/audio IDs. Браузер не нужен.
- Media replacement: path, codec/dimensions, loop/one-shot role и fallback.
- Runtime milestone: один репрезентативный маршрут в одном viewport.
- Release candidate: desktop + `390x844`, clean/resume/replay, основные исходы,
  sound on/off, reduced motion, media failure, console и overflow.

## 9. Definition of done

Игра готова, когда путь понятен без звука, сцены живут во время чтения, lifecycle
персонажей не нарушается после reload, финал сохраняется и предлагает replay,
а полный browser QA выполнен один раз на release candidate.

Отклонения от стандарта допустимы по драматургии, но фиксируются коротко в файле
конкретной игры. Новый mega-plan для этого не создаётся.
