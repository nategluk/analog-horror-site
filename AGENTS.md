# AGENTS.md

## Область действия

- Эти правила действуют для всего репозитория `analog-horror-site`.
- Проект — русскоязычный статический analog-horror ARG «Детский Жир».
- Основная аудитория молодая и мобильная; интерфейсы должны оставаться
  атмосферными, читаемыми и поддерживаемыми.
- Не превращать ARG в энциклопедию лора: механики должны расти из уже
  существующих страниц, действий игрока и последствий выбора.

## Границы работы

- Если пользователь просит сначала провести экспертизу или говорит
  «пока ничего не редактируй», предоставить независимый отчёт и остановиться
  до явного разрешения на правки.
- Сначала согласовывать драматургию и смысл новых сцен, затем писать код или
  генерационные промпты.
- При запросе на диагностику не внедрять исправления без отдельного указания.
- Сохранять пользовательские и несвязанные изменения в рабочем дереве.
- Не добавлять production-зависимости, серверную инфраструктуру или новые
  внешние сервисы без явного согласования.

## Источники правды

- Сценарий звонка Ирины: `content/irina/call-content.js`.
- Движок, UI, классификация и persistence: `js/app.js`.
- Хранилище личного дела: `js/dossier-store.js`.
- Механика эпизода: `docs/IRINA_CALL_GAME.md`.
- Content pipeline и локальная админка: `docs/IRINA_CONTENT_PIPELINE.md`.
- Производный экспорт реплик: `docs/IRINA_DIALOGUES.md`; не редактировать
  вручную.
- Канон Ирины находится вне репозитория: `~/md_lore/irina.md`.
- Перед изменением звонка прочитать оба handoff-документа выше.

## Контракт звонка Ирины

- Ирина остаётся эмоциональным центром эпизода.
- Сохранять неоднозначность: жертва, сотрудница, ненадёжная свидетельница и
  вербовщица могут сосуществовать.
- Держать реплики короткими и частыми; основной текстовый блок рассчитан
  примерно на четыре строки с прокруткой при крупном шрифте.
- Звук только добровольный и привязанный к узлам. Сюжетно важная информация
  обязана оставаться в видимом тексте.
- Классифицировать конкретные действия игрока, а не показывать числовые
  характеристики. Один ранний ответ не должен определять роль.
- `routeMarks` отражают расследование и открывают материалы отдельно от роли.
- Не менять ключи `tyndex_curator_call_v4`, `tyndex_staff_profile_v1` и
  `tyndex_mode` без явной миграции.

## Content pipeline

- На страницах с `js/app.js` сохранять порядок:
  `js/dossier-store.js` → `content/irina/call-content.js` → `js/app.js`.
- Не переносить classification helpers в content-модуль без отдельного
  архитектурного решения.
- После правок сценария запускать:

  ```sh
  node scripts/validate-irina-call-content.js
  node scripts/export-irina-dialogues.js
  node scripts/smoke-irina-call.js
  ```

- Локальный Copy Desk запускается командой `node scripts/admin-server.js`
  и доступен только на `http://127.0.0.1:8787/admin/`. Инспектор узлов
  Ирины: `http://127.0.0.1:8787/admin/nodes.html`.
- Сохранение через админку должно быть surgical: не форматировать весь
  `call-content.js`, не трогать соседние узлы и сохранять неизвестные поля
  choice, включая `image` и `imageAlt`.
- `admin/` и `scripts/` исключены из GitHub Pages через `_config.yml`.

## Медиа и CCTV

- Последовательные CCTV-фрагменты переключать по событию `video.ended`,
  поочерёдно и без повтора завершившегося файла.
- Сохранять отдельную haunted-video → noise ветку.
- Автоматическое и ручное переключение канала должны использовать общий
  переход и короткий звук смены канала.
- Статическая проверка недостаточна: инициировать реальное browser event и
  проверить видимое состояние, `HTMLVideoElement.loop` и консоль.

## UX и STAFF

- Проверять desktop и мобильный viewport примерно `390x844`.
- На узких экранах сохранять контролируемую горизонтальную прокрутку
  навигации без переполнения основного контента.
- Предпочитать понятные подписи декоративным кодам.
- Для STAFF использовать формулировку
  «закрепление личного дела за адресом восстановления», а не регистрацию
  аккаунта.
- Аватары игрока косметические; карточка игрока должна выглядеть частью
  общей кадровой базы.
- Не заявлять, что реальное email-восстановление работает, пока опубликованный
  frontend, письмо и второй девайс не проверены.

## Проверка изменений

- Для изменённых JS-файлов выполнять применимый `node --check`.
- Всегда запускать `git diff --check`.
- Для UI-изменений проводить реальный browser QA, а не ограничиваться
  синтаксисом.
- После навигации или существенного DOM-изменения делать новый Playwright
  snapshot перед использованием element refs.
- Для звонка проверять чистый и сохранённый сеанс, обе роли, ключевые
  accept/decline ветки, STAFF-артефакты и отсутствие ошибок консоли.
- Не очищать пользовательский `localStorage`, если чистый прогон не требуется
  явно; удалять только конкретный тестовый ключ.

## Git и публикация

- Не включать `.DS_Store`, `.env`, секреты и временные browser-артефакты.
- Не пушить и не публиковать без явной просьбы пользователя.
- Обычный путь публикации: пользователь делает commit и `Push origin` через
  GitHub Desktop.
- Локальный commit не равен публикации; дождаться rebuild GitHub Pages перед
  проверкой публичной версии.
- После публикации сначала предоставить категоризированный отчёт desktop /
  mobile без правок, затем обсуждать и внедрять исправления.
